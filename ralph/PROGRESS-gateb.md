Attenzione: FVMAIN al 99% (48 byte liberi): un altro driver non entra senza ridurre qualcosa.
- **Come funziona:** all'entry del driver si allocano 4 pagine EfiReservedMemoryType (una per CPU, BSP incluso, perche' acpigen richiede un `parked_address` unico per ogni GICC con parking), `ProcessorId=0xFFFFFFFF`, `JumpAddress=0`, ProcessorId atteso (= indice CPU = `cpu_interface_number`) a +0xFF0, stub copiato in +0x800, cache ripulita. A ReadyToBoot: per ogni core 1..3 sveglia il redistributor (`GICR_WAKER.ProcessorSleep=0`) e chiama PSCI `CPU_ON` (0xC4000003, target = MPIDR = indice, entry = mailbox+0x800, context_id = mailbox) tramite `ArmMonitorLib` (il conduit HVC/SMC lo legge dal DTB). Lo stub: abilita la CPU interface GICv3 (ICC_SRE/PMR/IGRPEN1), poi loop WFE sulla mailbox come da spec; al via azzera JumpAddress, DSB, X0=mailbox, BR.
- **Fonti verificate:** conduit PSCI di QEMU virt (`hw/arm/virt.c`, righe ~2951-2955): SMC se c'e' EL3 (secure=on), HVC altrimenti (nostro caso `secure=off,virtualization=off`), DISABLED se nessuno dei due; i core secondari partono spenti. Spec parking e confronto Linux/U-Boot: `re/f0-acpi-requisiti-windows.md` sez. 3 (comportamento riscritto da noi, nessun codice copiato). PSCI CPU_ON 64 bit = 0xC4000003 (conoscenza della spec Arm DEN0022, non riletta qui).
- **[ipotesi] / punti incerti:**
  1. Windows ARM64 moderno potrebbe NON supportare piu' il parking (rischio principale gia' in `re/f0`); con PSCI_COMPLIANT=0 e parking v1 il comportamento e' non documentato.
  2. Processor ID: usiamo `cpu_interface_number` (come Linux); su GICv3 senza compat la spec dice 0 per tutti: se Windows scrive 0 su tutti, lo stub non si sveglia (nessun match su ID 1..3). Mitigazione futura: accettare anche 0 o confrontare l'MPIDR.
  3. Il risveglio di Windows e' un interrupt/IPI (SGI): non necessario, lo stub fa polling con WFE; in HVF WFE e' trattato quasi come NOP (busy loop sui core, solo fino all'avvio dell'OS).
  4. Windows parte con i core in EL1; PSCI CPU_ON li avvia in EL1 nel nostro setup (nessun EL2) = stato richiesto dalla spec; da verificare nel trace.
  5. Wake dei redistributor e abilitazione ICC fatti da noi per rispettare "GIC CPU interface enabled" della Tab. 1; se Windows li riconfigura, nessun danno, ma non e' dimostrato che servano.
  6. I core sono accesi a ReadyToBoot, non a ExitBootServices: se un boot option fallisce e se ne prova un altro, la mailbox resta valida (flag `mStarted`).
  7. `PARKING_NCPUS = 4` e' fisso: usare `-smp 4`.
