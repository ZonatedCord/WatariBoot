## 1. Conventions
- Offsets in hexadecimal; widths in bits; `RW`, `RO`, `WO`, `RAZ/WI` (reads zero, writes ignored), `RAO/WI`.
- "Faithful" = complete architectural behavior, tested by the oracle. "Static" = constant value. "State" = value maintained by the vGIC. "Log-once" = ignored but logged only once (anti-noise).
- Every MMIO access to a virtual region arrives as a stage-2 abort (EC 0x24) with `ESR.ISV=1` (register and size known). If `ISV=0` the layer **does not guess**: panic with dump (R-06 in RISKS).

| Secondary cores | already started by m1n1 and halted waiting; the FDT reports `enable-method = "spin-table"` and `cpu-release-addr` for each core [hypothesis: to be read in m1n1 `kboot.c`/`smp.c`]; the layer writes the entry address into the release-addr and issues `SEV` |

## 3. Hand-off Watari EL2 → EDK2
### 3.1 CPU state on entry (every vCPU that starts)
| Element | Value |
|---|---|
| Level | EL1h (`SPSel=1`) |
| `PC` | QEMU: `0x0` (pflash0); t8103: entry declared in the image header |
| `x0` | physical address of the patched FDT; `x1..x30 = 0` |
| `DAIF` | all masked (D, A, I, F = 1) |
| `SCTLR_EL1` | RES1 bits only; MMU, D and I caches off |
| GIC state seen by EDK2 | vGIC at reset: all interrupts disabled, `GICD_CTLR=0`, **`GICR_WAKER.ProcessorSleep=0` for every vCPU that starts** (EDK2's `ArmGicV3Dxe` never does the wake handshake; verified in M1-4, F-21; Windows does it and is not harmed by an awake redistributor). The vGIC model itself resets with `ProcessorSleep=1`; the hand-off calls `vgic_vcpu_wake()` |
| `CNTVOFF_EL2` | 0; `CNTFRQ_EL0` as physical (24 MHz on M1 [verified: PB/F0]) |

### 3.2 Patched FDT (**in-place** modifications, no reallocation)
| Node/property | Modification |
|---|---|
| `/memory/reg` | layer region removed. **QEMU bench (M1-4, verified):** the layer is a `-kernel` Image at `0x40080000`, QEMU refuses an image at the top of RAM (F-21), so the first 2 MB are cut: base `0x40000000` -> `0x40200000`, size reduced (same property length, patched in place by `el2/boot/fdt.c`). On M1 the region can sit at the top, size only reduced. |
| `/psci/method` | `"smc"` → `"hvc"` (same length, in-place patch). In QEMU with `virtualization=on` the conduit is SMC [verified: `hw/arm/virt.c`] |
| `/cpus/cpu@N/reg` | virtual MPIDR (see §6.3); `enable-method` from `"spin-table"` to `"psci"` and removal of `cpu-release-addr`: lengths change, so on M1 the `/cpus` node is rebuilt in the hand-off buffer (see note below) |
| `/chosen/watari,el2` (new, in an additional buffer) | properties in §3.3 |
| GIC node | in QEMU: already `arm,gic-v3` at the real addresses (which are also the virtual ones); on M1: new node `/watari-intc` (`compatible = "arm,gic-v3"`, `reg = <GICD GICR>`, `redistributor-stride = <0x20000>`) |
| FDT address handed to EDK2 | **QEMU bench (M1-4):** x0 = a copy of the patched FDT at `0x40000000` (hand-off buffer, mapped in stage 2, outside `/memory`), because `DebugLibFdtPL011Uart` in PrePi reads the FDT at `PcdDeviceTreeInitialBaseAddress` (default `0x40000000`) before PrePi has learnt the real address (F-21). The copy is only the used part of the blob (`fdt_used_size`, QEMU leaves a 1 MB `totalsize`) and its `totalsize` is set accordingly. |
| `/timer/interrupts` | PPIs 13, 14, 11, 10 (GSIV 29, 30, 27, 26) as QEMU [verified: README acpigen] |
Note: where the in-place patch is not enough (different lengths) the layer **copies** the FDT into its own buffer (`WEL2_FDT_BUF`, 256 KB) and rebuilds it with a minimal writer; this choice lives in `wel2-fdt` and is invisible to EDK2. The M1 FDT contains many nodes: the writer copies everything verbatim except the nodes listed above.

## 4. Emulated MMIO map
| Region | QEMU (M0-M2) | t8103 (M3) | Size | Stage-2 treatment |
|---|---|---|---|---|
| GICD | `0x0800_0000` [verified: README acpigen] | `0xF_0000_0000` [hypothesis: as NTASP `0xf00000000`, verified: Mu audit] | 64 KB | trap on every access (MMIO hook) |
| GICR (vCPU *i*) | `0x080A_0000 + 0x20000·i` [verified: README acpigen] | `0xF_1000_0000 + 0x20000·i` | 128 KB per vCPU (RD_base 64 KB + SGI_base 64 KB) | trap |
| MSI Frame (GICv2m) | `0x0802_0000`, SPI base `0x50`, count `0x40` [verified: F-11] | `0xF_2000_0000`, SPI base 928 (=0x3A0), count 32 [hypothesis] | 4 KB | QEMU: **passthrough** (QEMU devices really write to `SETSPI_NSR`); t8103: trap, `SETSPI_NSR` ignored (no device uses it in v1) |
| Layer region | reserved high RAM | reserved high RAM | 64 MB [hypothesis] | **unmapped** (fault → panic with log) |
| Other peripherals | passthrough | passthrough (identity) with Device-nGnRnE | — | RAM: Normal WB; MMIO: Device-nGnRnE |

Why in QEMU the virtual addresses coincide with the real ones [hypothesis, reasoning]: the QEMU devices (virtio, NVMe, xHCI) write MSI messages to the address that Windows read from the MADT, an address that DMA writes do not translate through stage-2. With equal addresses the `acpigen -m qemu-virt` MADT of the V1 control is reused **without changes**; the real GICD/GICR remain reachable only from EL2 (own EL2 map).

## 5. Virtual distributor (GICD): registers and fidelity
Model: GICv3, **single security state** (`SecurityExtn=0`, `DS=1`), affinity routing always on, without LPI/ITS/MBIS, `A3V=1`, `RSS=0`, `No1N=0`. The configuration is architecturally valid: `DS` is RAO/WI when only one Security state exists, `ARE` is RAO/WI when GICv2 compatibility is not implemented [verified: GIC §12.9.4 pp.12-545/12-548]. That this is also what KVM presents to guests remains [hypothesis: from memory of the KVM code, not copied]; the **QEMU oracle** decides in case of difference.

| Offset | Register | Behavior | Fidelity / note |
|---|---|---|---|
| 0x0000 | `GICD_CTLR` | bit0 EnableGrp0, bit1 EnableGrp1, bit4 ARE (RAO/WI), bit6 DS (RAO/WI), bit7 E1NWF (RAZ/WI), bit31 RWP **always 0** | **Critical.** Windows writes ARE+EnableGrp1 and probes RWP: RWP never 1 [hypothesis: Windows behavior]. Single-security-state layout (bit0 EnableGrp0, bit1 EnableGrp1, bit4 ARE, bit6 DS, bit7 E1NWF, bit31 RWP) [verified: GIC §12.9.4 pp.12-547/548]; RWP is read-only and "0 = no write pending", so an always-0 RWP is architecturally valid; E1NWF may be RAZ/WI (IMPLEMENTATION DEFINED); bit8 `nASSGIreq` is RES0 (no GICv4.1) |

Writes to reserved registers: `RAZ/WI` with log-once. Misaligned accesses or of a disallowed size: panic with dump (guest errors are not hidden in v1).

### 6.3 Virtual MPIDR and identification registers
- `VMPIDR_EL2` of vCPU *i*: **flat**, `Aff0 = i`, `Aff1=Aff2=Aff3=0`, `U/MT=0`, bit31 RES1 [verified: ARM ARM D24.2.218 pp.D24-10099/10100: Aff3 [39:32], bit31 RES1, U bit30, MT bit24; the reset value is UNKNOWN, so the layer must write `VMPIDR_EL2` on every core]. Reason: the SGI target list uses Aff0 (16 bits) and the rest is decoded with a simple rule; the MADT of the `t8103-el2` model must use the same values (`acpigen` task).
- `VPIDR_EL2` = the core's real `MIDR_EL1` (E/P remain distinguishable: the MADT/PPTT declares the efficiency class).
- `ID_AA64PFR0_EL1` (trap `TID3`): the `GIC` field (bits 27:24) read as **1**, the rest unchanged [verified: ARM ARM D24.2.92 p.D24-9280: `GIC` bits [27:24], 0b0001 = GICv3.0/4.0 system-register interface, 0b0011 = GICv4.1; `HCR_EL2.TID3` bit18 traps EL1 reads of `ID_AA64PFR0_EL1` with EC 0x18, D24.2.61]. Reason: lesson F-08 (on HVF the field was 0 even with a usable GIC); a firmware that decides from the field would choose GICv2. The other `ID_AA64*`: passthrough of the real value, with masking of unsupported features (e.g. SPE via `ID_AA64DFR0_EL1.PMSVer` [35:32], nesting via `ID_AA64MMFR2_EL1.NV` [27:24]: both fields exist [verified: ARM ARM D24.2.79, D24.2.89]) listed in the `sysreg_overrides` table [hypothesis: which fields M1 must mask is a design decision].

### 7.2 Guest `ICC_*` registers to intercept (`TRAP_EMULATE` mode)
> **Status (2026-10-20, #52/#54):** variant A is implemented in the QEMU spike (`el2/vgic/vcif.c`, `el2/boot/cpuif.c`): `ICH_HCR_EL2 = En | TALL0 | TALL1 | TC | TDIR`, all rows below emulated, mode chosen at boot by build default or `/chosen/bootargs` `wel2.cpuif=hw|trap` (the "parameter, not a code change" of the closing paragraph). All encodings are **[verified: GIC §12.2, per-register "Accessing" sections]** (M0-A); the `TC`/`TALL`/`TDIR` column was also checked against each register's trap pseudocode, and three entries were corrected (marked). Routing rule from the pseudocode: with `IMO=1`/`FMO=1` an EL1 access to a Group 1 / Group 0 / common register is **redirected to the virtual CPU interface (`ICV_*`) in hardware** unless the matching trap bit is set, in which case it traps to EL2 with EC 0x18. Group 1 registers are governed by `TALL1` + `IMO`; Group 0 by `TALL0` + `FMO`; common registers by `TC` + (`FMO` or `IMO`) [GIC §4.6.4 p.4-67, §12.4.5 p.12-350].

### 7.3 SGI dispatch
Field layout of `ICC_SGI1R_EL1` [verified: GIC §12.2.22 pp.12-276/277]: Aff3 [55:48], RS [47:44] (RES0 while `ICC_CTLR_EL1.RSS=0`), IRM bit40, Aff2 [39:32], INTID [27:24], Aff1 [23:16], TargetList [15:0]; with IRM=1 the Aff fields and TargetList are RES0; target bits that match no PE "must be ignored by the Distributor". Preconditions: `ICC_SGI1R_EL1` written by vCPU *s*: `INTID[27:24]` ∈ 0-15, `TargetList[15:0]` (Aff0), `Aff1[23:16]`, `Aff2[39:32]`, `Aff3[55:48]`, `IRM[40]` (1 = all but self), `RS[47:44]` (0, RSS=0). Postconditions: for each destination vCPU with the SGI enabled (`GICR_ISENABLER0`) the pending bit is set; if destination ≠ current pCPU, `ipi_ops.send` is called. Errors: INTID out of range or non-existent destination → ignored + log (as per the architecture: non-existent destinations are ignored). Example: Windows sends SGI 0 to CPU 1 → `sgi_pending[1] |= 1` → `ipi_send(core 1)`.

### 7.4 Reference: list registers and VGIC type (verified in M0-A)
- `ICH_LR<n>_EL2` (64 bit, `S3_4_C12_C(12+n[3])_(n[2:0])`, n = 0..15) [verified: GIC §12.4.6 pp.12-353..356]: `State` [63:62] (00 invalid, 01 pending, 10 active, 11 pending+active), `HW` bit61, `Group` bit60, `NMI` bit59 (FEAT_GICv3_NMI only, else RES0), `Priority` [55:48] (≥5 bits implemented; unimplemented low bits RES0), `pINTID` [44:32] (with `HW=0`: bit41 = `EOI` maintenance request), `vINTID` [31:0] (≥16 bits). Two LRs with the same vINTID in state pending/active is UNPREDICTABLE; vINTID 1020-1023 with `State≠0` is UNPREDICTABLE. For hardware-linked interrupts the pending/active state lives in the physical distributor, so on the t8103 (no physical GIC) the layer uses only `HW=0` entries [design consequence].
- `ICH_VTR_EL2` (`S3_4_C12_C11_1`) [verified: GIC §12.4.9 pp.12-365/366]: `ListRegs` [4:0] = number of LRs minus 1; `TDS` bit19 (TDIR supported); `nV4` bit20 (1 in GICv3); `A3V` bit21; `SEIS` bit22; `IDbits` [25:23] (0 = 16 bits, 1 = 24 bits); `PREbits` [28:26] and `PRIbits` [31:29] (value = bits − 1, minimum 0b100 = 5 bits, so PRIbits ∈ {4,5,6}). The layer must read this register at boot and size the software state from it (the design assumes 8 LRs and 5 priority bits: [hypothesis] until read on the M1).
- `ICH_MISR_EL2` `S3_4_C12_C11_2`, `ICH_EISR_EL2` `S3_4_C12_C11_3`, `ICH_ELRSR_EL2` `S3_4_C12_C11_5` [verified: encodings, GIC §12.4].

### 8.1 `pirq_ops` (physical interrupt sources; normalizes IRQ **and** FIQ)
```c
typedef struct pirq_ops {
    const char *name;
    wel2_err_t (*init_bsp)(void);                     /* once, on the boot core */
    wel2_err_t (*init_cpu)(uint32_t pcpu);            /* on every core: aic_init_cpu sequence or equivalent */
    uint32_t   (*device_irq_count)(void);             /* e.g. 896 */
    uint32_t   (*poll)(uint32_t pcpu, pev_t *out, uint32_t max); /* drains the pending events; returns n */
    void       (*mask)(uint32_t irq);
    void       (*unmask)(uint32_t irq);
    wel2_err_t (*set_target)(uint32_t irq, uint32_t pcpu_mask);
    wel2_err_t (*set_trigger)(uint32_t irq, bool edge);
    uint32_t   (*intid_of)(uint32_t irq);             /* physical irq → virtual INTID */
    void       (*sw_trigger)(uint32_t irq, bool on);  /* test only: AIC SW_SET/CLR, fake */
} pirq_ops_t;
```
- `poll` precondition: called at EL2 with IRQ/FIQ pending for `pcpu`. Postcondition: every returned event is already acknowledged and, for `PEV_DEVICE`, **masked at the source**; an event is never returned twice. Errors: returns 0 events if spurious; log if `PEV_UNKNOWN` (the caller does not silently ignore it).
- Backend `pirq-aic-t8103`: `poll` reads `AIC_EVENT` (`base+0x2004`) until 0, decodes type (bits 23:16) and number (15:0); checks `IPI_SR_EL1`, the guest timers (`CNTP_CTL_EL02`, `CNTV_CTL_EL02` with `VM_TMR_FIQ_ENA_EL2`), `ICH_MISR_EL2` (→ `PEV_MAINT`), PMCR0/UPMCR0 (→ `PEV_PMU`, shutdown) [verified: F0 §1]. It does not read the AIC event in the FIQ branch (Mu bug D7).
- Backend `pirq-gic-qemu`: `poll` executes the physical `ICC_IAR1_EL1` at EL2; INTID 30/27 → `PEV_TIMER_P/V`; 25 → `PEV_MAINT`; SGI 0 reserved for the layer → `PEV_IPI`; other → `PEV_DEVICE`; then the physical `ICC_EOIR1_EL1` (priority drop + deactivate) immediately, since level semantics are handled above with mask.
- Backend `pirq-fake` (host): event queue programmable by the test.

## 9. PSCI and SMCCC via HVC
Convention: `HVC #0`; ID in `w0`, arguments `x1-x3`, result in `x0` (`x1-x3` zeroed when unused). 64-bit functions have prefix `0xC4`; 32-bit `0x84`. Function IDs, return codes and conventions below were checked in M0-A against PSCI DEN0022 F.b (PSCI 1.3) and SMCCC DEN0028 1.7 H: Fast call = bit31, SMC64 = bit30, owner in bits 29:24 (4 = Standard Service, 6 = Vendor Specific Hypervisor), `HVC #0` mandatory, non-zero HVC immediates designated for hypervisor vendors [SMCCC §2.5 Table 2-1 p.15, §2.10 p.18]; arguments `W0` = FID, `X1-X17` (SMC64) or `W1-W7` (SMC32), results `X0-X17`, `X4-X17` preserved unless results; unused result registers may be preserved or set to a constant such as zero [SMCCC §2.6/2.7 pp.16-17]; PSCI over HVC is allowed when EL3 is absent [PSCI §5 introduction].

| Function | ID | Response |
|---|---|---|
| `SMCCC_VERSION` | `0x8000_0000` | `0x0001_0001` (1.1; bit31 = 0, major [30:16], minor [15:0]) [verified: SMCCC §7.2 p.29] |
| `SMCCC_ARCH_FEATURES` | `0x8000_0001` | `arch_func_id` = `0x8000_0000` or `0x8000_0001` → `SUCCESS` (0); `NOT_SUPPORTED` (-1) for everything else (no workaround declared) **[corrected in M0-A: the draft said NOT_SUPPORTED for everything, which violates SMCCC §7.3.6 p.31]** |
| `PSCI_VERSION` | `0x8400_0000` | `0x0001_0001` (PSCI 1.1: major [31:16], minor [15:0]) [verified: PSCI §5.1.1/5.3]; "like QEMU" stays [hypothesis] (test-bench behavior, oracle). A PSCI 1.1 implementation need not offer the optional functions (`SYSTEM_SUSPEND`, `CPU_FREEZE`, ...) [verified: PSCI Table 17 p.95] |
| `CPU_SUSPEND` | `0x8400_0001`/`0xC400_0001` | `WFI` and `SUCCESS` (standby state); power-down states → `INVALID_PARAMETERS` |

| ID | Function | Use |

| `0xC600_0000` | `WEL2_VERSION` | returns `'WEL2'<<32 \| version` |

## 10. Naming and error conventions
- Functions: `wel2_<module>_<verb>` or internal `<module>_<verb>`; constants `WEL2_*`; types `*_t`; backends `<family>-<platform>`.
- Registers: architectural name in lowercase with the suffix `_el1/_el2` in the wrappers `sysreg_read_icc_iar1_el1()`.
- Errors: always `wel2_err_t`; functions that cannot fail return `void`; `panic`s go through `log_panic(code, fmt, …)` with stable codes (`PANIC_S2_FAULT=1, PANIC_ISV0=2, PANIC_SERROR=3, PANIC_LOCK_TIMEOUT=4, PANIC_BAD_FDT=5, …`).
- Log: one line = `[t=<cnt> cpu=<n> mod=<m> ev=<e>] fields`; fields are hexadecimal integers; no long strings; the ring keeps 64 KB per CPU.
- No `TODO` in the main branch; known limits live in `RISKS.md`.

## 11. Usage examples (expected sequences)
1. **Starting a secondary CPU (Windows):** `HVC #0` with `x0=0xC4000003`, `x1=1` (MPIDR vCPU1), `x2=entry`, `x3=ctx` → `psci_handle` → `plat_ops.cpu_start(pcpu1, trampoline, vcpu1)` → returns `0` → pCPU1 runs the trampoline at EL2, initializes per-CPU, sets the vGIC reset state and does `ERET` to `entry` with `x0=ctx`.
2. **Enabling an SPI by Windows:** write to `GICD_ISENABLER1` (`0xF_0000_0104`) bit 25 → MMIO trap → `vgic_mmio_write` → state `enabled[57]=1` → action `pirq.unmask(25)` and `pirq.set_target(25, mask(IROUTER[57]))`.
3. **Timer:** see ARCHITECTURE §6.2; the M0 test verifies the sequence with a fake source.
