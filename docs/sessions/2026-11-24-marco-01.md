# Session 2026-11-24, Marco 01: bench tests for the 0xA0 (in progress)

## Bench matrix for F-43
`el2/boot/run-0xa0-matrix.sh` (new): one QEMU at a time, j293 GIC windows, 10-bit fake panel. Runs are under `$WATARI_DATA/logs/winram/a0-1124-*`. Results so far [verified: serial.log and shots]:

| Run | Cores | Tables | Result |
|---|---|---|---|
| `a0-1124-c1-e1` | 1 | `j293-e1` (1 CPU) | Windows Setup, driver page, no reset in 492 s |
| `a0-1124-c1-j293old` | 1 | `j293` (8 CPUs), firmware of the same commit (84f37c4) | `INTERNAL_POWER_ERROR (0xA0)` before the first screenshot at 42 s; red screen on the 10-bit panel, black when read as 8-bit |

The layer, the vGIC, the CPU-interface mode and the number of cores are the same in both runs; only the firmware's ACPI model differs. On the bench the tables that describe missing cores are enough to give the 0xA0 of F-43. That the M1's 0xA0 has the same cause is still [hypothesis]: the bench has no AIC/FIQ path. The other runs are in the queue.

## To plan: an M1-like QEMU machine (Marco's request)
Marco asked to keep this for the next development sessions: it would help to understand the hardware and to test faster than a hardware day.

What exists: the patched QEMU (`tools/qemu-watari`, `aic=on`, `ram-base=`), with device interrupts through an AIC. `plat_m1` is never selected on a bench.

What is missing (list and estimate from `re/qemu-aic-bench.md`, 3-5 days in all [hypothesis]):
1. A `-cpu` variant with the Apple sysregs the layer uses (timer FIQ enable, fast IPI, PMCR0 and the rest).
2. Timer and IPI delivered to the core as FIQ instead of GIC PPIs.
3. An `is_m1`-style FDT, so that `plat_select` picks `plat_m1`.
4. PMU, in the same `-cpu` variant [hypothesis: 1-2 more days]: no PMUv3 (`PMUVer = 0xF`), `HACR_EL2[56]` routing EL1 PMU accesses to EL2 as EC 0x3F with `AFSR1_EL2`, TPM/TPMCR as RES0, and PMC0 as a counter.

Order suggested: timer FIQ first (WinPE from a RAM disk with one core uses almost nothing else), then PMU, then IPI.

Limit: the model encodes our own assumptions. It finds bugs in our code, not wrong ideas about the hardware. Anything not measured on the M1 (the EC seen by the layer, the AFSR1 layout, the PMC0 width) stays [hypothesis] even if the bench passes.
