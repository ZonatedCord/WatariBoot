# Session 2026-11-16, Marco 01: Monday review, catch mode, handoff

## What happened
- Reviewed Ciani's Monday bundle and PR #90. Day-3 gate PASS. W2 and W1c stopped with an EL1 synchronous exception, ESR 0x02000000 (EC 0 = UNDEFINED), just after BDS started `BOOTAA64.EFI`.
- Monday's firmware was the right one: the FD hash in the logs (`a8cf6ee11e591b4c`) is `WATARI_M1_EFI-bgr8.fd`.
- DxeCore symbolization [verified]: the two PCs on the screen are return addresses. `+0x25744` is in `_CModuleEntryPoint`, and `+0x1ECA4` follows the `blr` in `CoreStartImage`. The fault is inside bootmgr at 0x9BED00?4.
- The EDK2 RNDR use is guarded by an `ID_AA64ISAR0` check, so it is not the cause.
- Lead [hypothesis]: bootmgr reads a register the M1 does not implement, most likely the PMUv3 (`PMCR_EL0`). bootcamparm.com's public log (3 Nov) mentions "stop before the PMCR_EL0 read".
- W2 only: the guest got `memory@806000000` (a 32 MB gap between m1n1 reservations, which appears with secondaries=True). USB DART tables sit at 0x806f7c000 and 0x807458000 in the E log. This is an open risk; W1c did not have it.

## Built today (branch `m3a-catch-mode`, pushed)
- Layer catch mode `wel2.catch` (default on for M1). MDCR_EL2 TPM, TPMCR, TDA, TDOSA, TDRA and HCR_EL2 TIDCP, TACR are set. PMU, debug, IMPDEF and ACTLR accesses are logged (`CATCH ...`) and emulated as RAZ/WI.
- New hypercall `WEL2_REPORT_EXC` (0xC6000005). EDK2's exception handler reports ESR, ELR, FAR and SPSR to the layer.
- Rung `ID0` in `monday.py`: a read-only ID-register dump through the m1n1 proxy. Run it with `--no-fault-probe` first.
- ADR `docs/adr/draft-f01-interop-reading.md`: the black-box route comes first, then limited interop reading, and only conclusions go in the repo (accepted by Marco).

## In flight when this was written
- Review fixes for catch mode (branch `m3a-catch-fixes`): the catch panel area is reduced to 3 rows (it was taking about 420 rows from the j293 GOP), overflow logging, guest-exception text no longer hides a later fatal, TIDCP SYS ops, OS lock state.
- EDK2 EL1 safety net (branch `m3a-el1-safety-net`, approved by Marco). On EC 0, our handler decodes only the MRS/MSR at ELR and emulates PMU, debug, AMU and RNDR registers as zero. It logs only the encoding and the PC.
- Bench: WinPE with `wel2.catch=1` (`TAG=catch1`, logs in `$WATARI_DATA/logs/winram/catch1/`).
