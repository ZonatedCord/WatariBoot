**Finding (loader fix).** The T16j loader allocated the ring as its own 32 MB block right after the EDK2 block. With `--pmlog` on a D2 jump the dry run printed `gfdt_dump: placement refused by the layer's rule (wel2_gfdt_place code 5)` and no `GUEST FDT CHECK` line (the dry run calls that "expected" with fake addresses): on the M1 the same refusal would have been exit 4, so **every `--pmlog` jump rung would have refused to jump**. Cause: the layer wants 64 MB of the range that holds EDK2's entry above the guest FDT (code 5 = `WEL2_GFP_UEFI_REGION`), and a ring cut out 32 MB above the entry leaves 32 MB. Fix (`watari-load.py` `pmlog_place`): with `--edk2` the ring sits at the start of the unwritten spacer block (D0's `BLOCK  guest` block), so there is no extra block (heap need unchanged), `LAYER`/`EDK2` keep D0's addresses and the entry's range stays whole; without `--edk2` the old own-block-last rule stays; `BLOCK CHECK` lists `pmlog block` and drops the spacer from the preview's list. Both D2 and W2 dry runs now end `GUEST FDT CHECK: PASS`, `BLOCK CHECK: PASS`. `test_pmlog.py` updated (three blocks, ring == spacer, D0 and D0 `--pmlog` print the same three block addresses).
