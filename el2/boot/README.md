# Watari EL2 - M0-C boot skeleton

First bootable skeleton of the Watari EL2 layer in QEMU TCG (no hardware, no downloads).

What it does (all **verified** by `run-qemu.sh`):
1. Enters at EL2 (`CurrentEL` printed), sets the stack and `VBAR_EL2`, prints via the PL011 at `0x09000000`.
2. Sets `HCR_EL2 = RW | IMO | FMO | AMO`, `SPSR_EL2` = EL1h with DAIF masked, `ELR_EL2`, and `eret`s to a tiny EL1 payload linked in the same image.
3. The EL1 payload prints, issues `HVC #0` with `PSCI_VERSION` (gets 1.1) and then `SYSTEM_OFF`.
4. The EL2 sync handler (lower EL, AArch64) recognizes `ESR_EL2.EC = 0x16`, implements `PSCI_VERSION` and `SYSTEM_OFF` (forwarded with `smc #0` to QEMU's PSCI: with `virtualization=on` the conduit is SMC), and answers anything else with `NOT_SUPPORTED`.
5. Any other exception prints `ESR/ELR/FAR/SPSR` and halts (never a silent hang, lesson F-14).

(`TSC=1`, vGIC-to-physical-GIC effects, SMP, `E2H=1`, the 16 KB granule, `TID3`, PAuth, `trap-notc` and the boot ladder came later, see below.)

## M1-1: stage-2 + virtual GIC (issue #50, first step)
- `HCR_EL2.VM=1`; identity stage-2 map, **4 KB granule** (the first spike; the granule is now selectable and 16 KB is the default, see "E2H = 1 and the 16 KB granule"), (M1-1 first step: 32-bit IPA, start level 1, RAM `0x40000000-0x7fffffff`; today 40-bit IPA over the whole RAM from the FDT, see below) Normal WB RAM, the rest Device-nGnRnE (execute-never).
- The physical GICD (`0x08000000`, 64 KB) and the first 8 GICR frames (`0x080A0000`, 8 x 128 KB) are **unmapped**: guest accesses take a stage-2 translation fault to EL2.
- EL2 data-abort handler (`EC=0x24`): decodes ISV/SAS/SSE/SRT/SF/WnR, rebuilds the IPA from `HPFAR_EL2`+`FAR_EL2`, calls `vgic_mmio_read/write` (`../vgic/vgic.c` is linked into the image), writes the register back for loads and advances `ELR_EL2` by 4. ISV=0, non-translation faults or addresses outside the GIC windows print ESR/FAR/HPFAR/IPA and halt (F-14).
- The physical GIC is left untouched in this step; the vGIC `effect` hook only logs.
- EL1 payload reads GICD_CTLR/TYPER (`0x0148001d`)/IIDR, GICR_TYPER (Last bit set), does the GICR_WAKER handshake, enables SPI 33 and sets its priority, then PSCI `SYSTEM_OFF`.
- Build needed `-mstrict-align` (F-18); since #53 only the MMU-off code keeps it (see Hardening).
- Run: `./run-m1.sh` (M1-1 checks) and `./run-qemu.sh` (M0 checks); both pass on the same image.

## Files
- `start.S`: arm64 Image header, reset path, `enter_el1`, vector table + context save/restore.
- `main.c`: exception handler, stage-2, data-abort/vGIC glue, boot arguments, `el2_main`.
- `util.c` (#53): UART, big/UART locks, format helpers, `memcpy`/`memset`, `dcache_clean_range`; built with `-mstrict-align` (the EL1 test payload calls it with its MMU off).
- `stage1.c` (#53, #58): boot arguments `wel2.e2h`/`wel2.gran`, EL2 stage-1 identity map (tables built MMU-off by `../vgic/pt.c` + `../vgic/maps.c`); `s1_enable` in `start.S` sets `HCR_EL2.E2H`, then switches MMU + caches on, on every core.
- `../vgic/vcif.c`, `../include/wel2_vcif.h` (#54/#52): virtual CPU interface model (LR fill/evict/harvest, ICC_* emulation), host-tested in `../tests/test_vcif.c`.
- `run-m1-5.sh` (#54): LR-overflow test; `run-all.sh`: every test in both modes.
- `boot.h`: shared declarations (frame layout, GIC addresses, module APIs).
- `gic_phys.c` (M1-2): EL2 owns the physical GICv3: `ICC_SRE_EL2` (SRE+Enable), GICD ARE+Grp1, redistributor wake, PPI 25 (maintenance) and PPI 27 (CNTV) as Group 1 level, priority 0x40, `ICC_PMR_EL1`=0xFF, `ICC_IGRPEN1_EL1`=1.
- `cpuif.c` (M1-2): virtual CPU interface. `ICH_HCR_EL2.En=1`, LR fill from `vgic_next_pending()`/`vgic_ack()`, harvest on guest EOI (LR invalid, `vgic_eoi()`), virtual timer line, ICC_SGI*R trap decoder.
- `payload.c`/`payload.S`: the EL1 test payload (M0 PSCI, M1-1 MMIO view, M1-2 OS-like GIC bring-up + timer + SGI) and its EL1 vector table.
- `linker.ld`: position-independent image (T6a): linked at 0 as a PIE, relocated by `start.S` to wherever the loader put it (QEMU: `0x40080000` = RAM base + `text_offset` 0x80000), stacks after the image. See "Position independence" below.
- `Makefile`: Homebrew LLVM (`clang --target=aarch64-none-elf`, `ld.lld`, `llvm-objcopy`).
- `run-m1.sh`: same harness with the M1-1 expectations (vGIC register values).
- `run-m1-2.sh`: M1-2 expectations (`timer irq 27 x5`, SGI trap, `sgi 1 received`, five INTID 27 lines).
- `psci.c` (M1-3): guest PSCI over HVC (`CPU_ON`, `CPU_OFF`, `AFFINITY_INFO`, `PSCI_FEATURES`, `MIGRATE_INFO_TYPE`, `PSCI_VERSION`, `SYSTEM_OFF`), firmware conduit = SMC to QEMU.
- `run-m1-3.sh`: M1-3 expectations on `-smp 4` (60 s timeout); since M2.x-2 also the re-target check (see "pirq" below).
- `pirq_qemu.c` (M2.x-2): backend of the pirq policy on the QEMU physical GICv3 (see "pirq" below).
- `run-qemu.sh`: builds, boots headless (20 s timeout) and checks the UART output; exit 0 = pass.

## M1-2: virtual interrupts (QEMU TCG, verified by `run-m1-2.sh`)
Mode: **hardware list registers** (`ICH_HCR_EL2` = En only, TALL0/TALL1/TC = 0). With `HCR_EL2.IMO=1` the guest's `ICC_IAR1/EOIR1/PMR/IGRPEN1/BPR1` at EL1 are the virtual `ICV_*` registers and run without traps. Trapped by EL2 (EC 0x18, ISS decoded in `cpuif_sysreg_trap`): only `ICC_SGI1R_EL1` / `ICC_ASGI1R_EL1` / `ICC_SGI0R_EL1` writes, which `IMO=1` traps by itself (GIC spec 4.6.4 p.4-67). Nothing else needs TRAP_EMULATE in QEMU. QEMU reports `ICH_VTR_EL2.SEIS=0`, so the M1 SEIS erratum (RISKS R-01) cannot be exercised here: on M1 `TALL1`/`TC` must be set and `cpuif.c` extended with the ICC emulation path.
- Interrupt life cycle: physical IRQ at EL2 (vector 9) -> `cpuif_flush()`: `vgic_next_pending()` + `vgic_ack()` (model marks it active; the LR owns pending/active) -> LR written Pending, Group 1, EOI=1 (HW=0) -> guest ack/EOI in hardware -> LR invalid + maintenance interrupt (PPI 25) -> harvest: `vgic_eoi()`, LR freed, level lines re-pend if still high.
- Virtual timer: guest programs CNTV directly (`CNTVOFF_EL2`=0, `CNTHCTL_EL2`=3). The physical PPI 27 is level: on arrival EL2 masks it at the redistributor, EOIs it, and the model line follows `CNTV_CTL_EL0` (ENABLE && ISTATUS && !IMASK); when the guest has silenced the timer, EL2 unmasks PPI 27 again. Group is hardcoded to Group 1 in the LRs (Windows uses Group 1 only).
- Not done in M1-2 (SPI forwarding and SMP came in M1-3): LR overflow (`UIE` underflow interrupt), `HW=1` LRs for physical-interrupt passthrough, EL2 stage-1 MMU.

## M1-3: SMP and peripheral interrupts (QEMU TCG `-smp 4`, verified by `run-m1-3.sh`)
`./run-m1-3.sh` boots `-M virt,virtualization=on,gic-version=3 -cpu max -accel tcg -smp 4`; it also passes with `-accel tcg,thread=single`. `run-qemu.sh`, `run-m1.sh`, `run-m1-2.sh` (all `-smp 1`) still pass on the same image, and `make -C el2 test` has 5 suites (the new one is `test_vgic_smp.c`).

**Cores and vCPUs.** The number of cores is discovered by walking the physical `GICR_TYPER` frames (stride 0x20000) until the Last bit (`gic_phys_discover`); vCPU i = core i, affinities taken from `GICR_TYPER[63:32]`, so the vGIC has exactly as many redistributors as the machine has cores, and `GICR_TYPER.Last` is set only on the last one (host-tested). `TPIDR_EL2` holds the core index. `VPIDR_EL2`/`VMPIDR_EL2` are set from the physical MIDR/MPIDR on every core, so an MPIDR means the same to the guest and to PSCI.

**PSCI (`psci.c`, PSCI DEN0022F.b).** Both SMC32 and SMC64 function ids for CPU_ON (5.6) and AFFINITY_INFO (5.7). `CPU_ON`: target must be a valid MPIDR (bits outside Aff3:Aff2:Aff1:Aff0 clear, else `INVALID_PARAMETERS`; unknown core the same), entry 4-byte aligned inside guest RAM (else `INVALID_ADDRESS`), `ALREADY_ON` / `ON_PENDING` by core state; then SMC `CPU_ON` to the firmware with `secondary_entry` as the EL2 entry point. The secondary (`start.S` -> `el2_secondary_main`) sets its stack (slot = `wel2_core_index(MPIDR)` = Aff1*4 + Aff0, `include/wel2_coreidx.h`; out-of-range cores park, CPU_ON refuses them), `VBAR_EL2`, the shared stage 2 (same VTCR/VTTBR), `VPIDR/VMPIDR`, its own physical redistributor + CPU interface and `ICH_HCR_EL2`, marks itself ON and `eret`s to EL1h with all DAIF masked, MMU off and `x0` = context_id (6.4.3). `CPU_OFF` (5.5): the core resets its vCPU in the vGIC (redistributor asleep again, private IRQs dropped), clears its LRs, puts the physical redistributor to sleep, publishes OFF, releases the big lock and calls the firmware `CPU_OFF`; `DENIED` on the last ON core. `AFFINITY_INFO`: ON 0 / OFF 1 / ON_PENDING 2, level != 0 -> `INVALID_PARAMETERS` (allowed since PSCI 1.0). `PSCI_FEATURES`: 0 for what is implemented, `NOT_SUPPORTED` otherwise. Everything else (CPU_SUSPEND, SYSTEM_RESET, ...) returns `NOT_SUPPORTED`; EL2 never hangs silently (F-14).

**Locking.** All EL2 shared state (vGIC model, per-core CPU-interface state, core states) is under one big lock taken in `el2_exception`; UART output has its own lock so lines do not interleave (`puts_`, `put_kv`, `put_kn` write one line atomically). Spins are bounded and report. See F-20 for the caveat on real hardware (exclusives on Device memory).

**SGIs between vCPUs.** The guest's `ICC_SGI1R_EL1` write traps (`IMO=1`); `vgic_sgi_send_mask()` marks the SGI pending on every target vCPU and returns the target mask (target list, Aff1..3, IRM tested in `test_vgic_smp.c` / `test_vgic_sgi.c`). After any change of shared state, `cpuif_kick_others()` sends the **physical SGI 15** (`SGI_KICK`, reserved for EL2: guest SGIs are virtual and never reach the physical distributor, so INTID 15 of the physical GIC is free) to each other ON core that has a deliverable interrupt and a free LR. The target takes the IRQ at EL2 (also from WFI at EL1), runs `cpuif_flush()` and the interrupt lands in its list registers.

**SPIs.** The vGIC effect hook is wired to the physical distributor (`cpuif_vgic_effect`): `SET_TARGET` writes the physical `GICD_IROUTER` with the target core's affinity; `UNMASK_SPI` sets Group 1, priority 0x40 and enables it; `MASK_SPI` disables it. A forwarded SPI arrives on its core at EL2: EL2 masks it at the GICD, EOIs it and raises the model line; when the guest EOIs the injected vIRQ (harvest) the line is dropped, `vgic_eoi()` runs and the SPI is unmasked, so a still-asserted level interrupt fires again and a silenced one does not. SPIs are assumed level-sensitive at the physical GIC (as all QEMU virt device SPIs are). The test uses the **PL031 RTC alarm (SPI 2 = INTID 34)**: the guest programs `RTCMR`/`RTCIMSC` directly (the RTC is mapped device memory in stage 2), routes INTID 34 to the last core with a 64-bit `GICD_IROUTER` write and enables it; the handler clears `RTCICR`. No physical `GICD_ISPENDR` fallback was needed.

**Not done / open (M1-3).** EL2 stage-1 MMU (needed for the locks on hardware, F-18/F-20); LR overflow (`UIE`) and a real fix for the kick-storm guard; secondary stack-slot formula is M1-shaped but untested on hardware; edge-triggered physical SPIs and `GICD_ICFGR` forwarding; SPI priority fixed at 0x40 at EL2 (the guest's priority only orders vIRQs); `HW=1` LRs; the TRAP_EMULATE path for the M1 SEIS erratum (F-19) is still untested; CPU_SUSPEND / SYSTEM_RESET.

## M1-4: EDK2 at EL1 on top of Watari EL2 (QEMU TCG `-smp 4 -m 2G`, verified by `run-m1-4.sh`)
`./run-m1-4.sh` builds the chain image (`make chain` -> `build-chain/wel2.bin`: `-DWEL2_CHAIN`, no EL1 test payload, `HCR_EL2.TSC=1`) and boots it together with `ArmVirtQemuKernel` (`tools/build-edk2-kernel.sh`, run once; output `$WATARI_DATA/build-kernel/QEMU_EFI-kernel.fd`):

    qemu-system-aarch64 -M virt,virtualization=on,gic-version=3 -cpu max -accel tcg -m 2G -smp 4 -nic none \
        -kernel build-chain/wel2.bin -device loader,file=QEMU_EFI-kernel.fd,addr=0x40280000,force-raw=on

Success = EDK2 prints `BdsDxe: Press any key to enter the Boot Manager Menu` (about 5 s with `-nic none`; `WITH_NIC=1` keeps the virtio NIC and adds the PXE attempt `failed to load Boot0002`, about 60 s) and the layer log shows vGIC traps handled and timer interrupts injected. `run-qemu.sh`, `run-m1.sh`, `run-m1-2.sh`, `run-m1-3.sh` and `make -C el2 test` still pass (the default `make` image keeps the payload). `ArmVirtQemuKernel` booted alone with plain QEMU (`-kernel QEMU_EFI-kernel.fd`, no layer) also reaches the Boot Manager (checked first).

**Chain, step by step.** (1) QEMU loads the layer as an arm64 `Image` at `0x40080000`, the FDT at `0x48000000`, x0 = FDT, and enters at EL2. (2) The layer does its normal init (stage 2, vGIC, physical GIC, list registers). (3) `chain_to_edk2()` patches the FDT in place (`fdt.c`), copies it to `0x40000000`, wakes the boot vCPU in the vGIC and ERETs to the EDK2 image at `0x40280000`. (4) EDK2's header trampoline (`adr x1, .; b 0x8000`) lets the relocatable PrePi fix itself up at that address; the rest is a normal ArmVirtQemu boot, except that every GIC register access is a stage-2 fault handled by the vGIC and every PSCI call is an HVC.

**Boot protocol handed to EDK2 (Linux arm64 booting, entry state).** Image 4 KB aligned at `0x40280000` (the 2 MB after the layer's carve-out + the image's `text_offset` 0x80000); `x0` = physical address of the FDT (`0x40000000`), `x1 = x2 = x3 = 0` (`enter_el1` zeroes them); MMU off, D-cache off (`SCTLR_EL1` = RES1 only); PSTATE EL1h, DAIF masked. Differences from the plain protocol: entered at EL1 because the layer owns EL2; the FDT is patched; and it sits at the RAM base because of PrePi's early debug output (F-21).

**FDT patch (`fdt.c`, no libfdt, all in place).** `/memory/reg`: first 2 MB removed (base `0x40200000`, size `0x7fe00000`; the carve-out holds the FDT buffer `[0x40000000,0x40080000)` and the layer `[0x40080000,0x40200000)`); `/psci/method` `"smc"` -> `"hvc"`; `/timer/interrupts` is only read and logged.

**PSCI conduit: decision = patch the FDT to `hvc`** (INTERFACES 3.2/9). The guest then calls the layer directly (HVC traps to EL2 with `HCR_EL2.HCD=0`), nothing has to be emulated, and it is the conduit Windows will be told through the FADT. `HCR_EL2.TSC=1` stays on as a backstop: with `TSC=0` a stray SMC would go straight to QEMU's PSCI (with `virtualization=on` it is SMC), start a core at EL2 without layer init and break the machine silently. A trapped SMC gets `NOT_SUPPORTED`, `ELR` advanced (the preferred return address of a trapped SMC is the SMC itself) and a log line. `PSCI_SYSTEM_RESET` is forwarded to QEMU like `SYSTEM_OFF`.

**Timer: EDK2 uses the EL1 virtual timer, INTID 27 (PPI 11).** `ArmVirtPkg/ArmVirt.dsc.inc` selects `ArmGenericTimerVirtCounterLib`, so `TimerDxe` programs `CNTV_CVAL/CTL_EL0`; it registers handlers for all four timer PPIs but only 27 fires. That is the path the layer already delivers since M1-2 (physical PPI 27 -> mask -> list-register injection; `CNTHCTL_EL2` = 3 keeps EL1 access to counters and timers), so no change was needed in the timer code. A guest using the EL1 physical timer (PPI 30) would need PPI 30 enabled and forwarded like 27.

**Stage 2 changes.** IPA space 40 bits (T0SZ=24, start level 0): EDK2 touches the PCIe high ECAM (`0x4010000000`). RAM `0x80000000-0xbfffffff` is Normal (a `-m 2G` machine). In the chain image the layer's own pages (`__image_start` to the end of the 2 MB carve-out) are unmapped: a guest access takes a translation fault and EL2 prints ESR/FAR/IPA and x0-x30 (it never happened in the runs).

**Observed (excerpt of the last `run-m1-4.sh`).**

    Watari EL2: FDT from QEMU at 0x0000000048000000
    Watari EL2: FDT /memory base now 0x0000000040200000

    Watari EL2: eret to EDK2 at EL1, entry = 0x0000000040280000

**Not done / open (M1-4).** EDK2 never calls `CPU_ON` in this firmware, so SMP under EDK2 is untested (the secondary-core wake-up is in the chain build but never ran); the UEFI Shell is not reached automatically (the firmware waits for a key at the Boot Manager prompt); PPI 27 stays masked if the model ever cannot deliver it (F-21); PCI devices with 64-bit BARs (high MMIO window) were not exercised.


## Hardening before M2 (#54, #53, #52; QEMU TCG, all verified by `./run-all.sh`, both modes)
`./run-all.sh` runs the host tests and `run-qemu`, `run-m1`, `run-m1-2`, `run-m1-3`, `run-m1-5` (plus its `noeoi` variant) and `run-m1-4` with `CPUIF=hw` and `CPUIF=trap` (`SKIP_M14=1` skips the EDK2 chain test, which needs the data disk). Dead ends and limits: `docs/FAILURES.md` F-22.

**Mode switch (#52).** The virtual CPU interface runs in `HW` mode (list registers only, no ICC traps; the default) or `TRAP_EMULATE`. Chosen at boot: build default `-DWEL2_CPUIF_TRAP_DEFAULT=1` (e.g. `make XFLAGS=-DWEL2_CPUIF_TRAP_DEFAULT=1`), overridden at run time by `/chosen/bootargs`: QEMU `-append "wel2.cpuif=trap"` (or `hw`). The test scripts take `CPUIF=trap`. A second boot argument, `wel2.test=noeoi`, is a test knob (SGI list registers without the EOI maintenance bit, so only the underflow interrupt refills them).

**LR overflow (#54).** `cpuif_flush()` = hardware LRs into the model (`vcif_*`), harvest, fill, write back what changed. More pending interrupts than LRs wait in the vGIC model and enter the LRs in priority order as they free up: by the EOI maintenance interrupt each LR carries, and by the underflow interrupt (`ICH_HCR_EL2.UIE`, armed only while interrupts overflow and at least two LRs are valid). `NPIE` is deliberately not used (F-22). A pending-only LR is evicted (`vgic_requeue`) when a strictly higher priority interrupt arrives and every LR is taken. `run-m1-5.sh`: with IRQs masked the EL1 payload sends 8 SGIs to itself (QEMU has 4 LRs; priorities shuffled against INTID order) and checks that all 8 arrive exactly once in priority order; then 4 low-priority SGIs plus one much better SGI: the better one must come first. Counters printed at SYSTEM_OFF: injections, evictions, maintenance and UIE interrupts. `NOEOI=1 ./run-m1-5.sh` requires UIE to have fired (3 times in the last run); in `trap` mode UIE is moot (EOIR traps, EL2 refills at once).

**EL2 stage 1 (#53).** Identity map, 4 KB granule, 39-bit VA (`T0SZ` 25, start level 1): `0-1 GB` Device-nGnRnE execute-never (2 MB blocks), RAM Normal WB Inner-Shareable (`MAIR_EL2` Attr1 = 0xff, `TCR_EL2` IRGN0/ORGN0 = WB WA, SH0 = ISH). In the first 2 MB of RAM (4 KB pages, where the layer lives): code read-only + executable, rodata read-only XN, FDT buffer / data / bss / stacks RW XN; the linker script page-aligns the sections and asserts that the layer fits the first 2 MB. `stage1_build()` (C, `-mstrict-align`, MMU off) runs on the boot core; `s1_enable` (assembly, registers only) sets MAIR/TCR/TTBR0, invalidates TLB + I-cache and sets `SCTLR_EL2.M/C/I` (A, WXN, EE cleared) on the boot core and, before any C, on every secondary; each checks the bits afterwards. **E2H: at the time of #53 the layer ran with `HCR_EL2.E2H = 0`** (E2H0 layout of `TCR_EL2`: PS[18:16], RES1 bits 31 and 23; Arm ARM D24.2.194); the E2H = 1 layout is now executed in QEMU too (section "E2H = 1 and the 16 KB granule"). Consequences: the spin locks are exclusives on Normal Inner-Shareable memory (F-20); `-mstrict-align` is gone for EL2 code (`vgic.c` now contains the unaligned stores of F-18 and runs); it stays for `stage1.c`, `util.c`, `payload.c` because they run with the MMU off. The patched FDT is cleaned from the data cache before the guest starts with caches off. Mapping only the RAM that exists: done later from the FDT (see "Hardening follow-ups" below). Not done: cache maintenance for the page tables on real hardware. The 4 KB granule described here is now one of two (see below).

**TRAP_EMULATE (#52).** `ICH_HCR_EL2` = `En | TALL0 | TALL1 | TC | TDIR` (`TDIR` only if `ICH_VTR_EL2.TDS`), i.e. variant A of INTERFACES 7.2. Every guest access to `ICC_IAR1/EOIR1/HPPIR1/BPR1/CTLR/IGRPEN0/1/DIR/RPR/PMR/AP0Rn/AP1Rn/IAR0/EOIR0/HPPIR0/BPR0` traps (EC 0x18); `cpuif_sysreg_trap()` decodes the ISS, loads LR + VMCR + AP into the model, `vcif_*` does what the `ICV_*` hardware would (signalling needs priority < PMR, Group 1 enabled, group priority < running priority; IAR: LR pending -> active + AP bit; EOIR: priority drop, deactivate if EOImode 0; PMR/BPR/IGRPEN/EOImode live in `ICH_VMCR_EL2` so the hardware's own vIRQ signalling follows), writes back what changed and advances `ELR_EL2`. The guest still gets its vIRQ from the hardware (pending LR + VMCR); only the registers it reads are emulated. `ICC_SGI*R_EL1` traps in both modes. QEMU has `SEIS = 0` (F-19): this tests the logic, not the M1 erratum. `ICC_PMR_EL1` writes are counted: **1 write, 998 IAR1/EOIR1 pairs during the whole M1-4 EDK2 boot** (single core; printed every 100th timer tick when something changed, and at SYSTEM_OFF; `run-m1-4.sh` prints the last report) - input for #43; the Windows figure is the M2 measurement.

## E2H = 1 and the 16 KB granule (M3a prep; #58, #60; F-27; QEMU TCG `-cpu max`, host tests)
The real M1 differs from the QEMU spike in two ways that `-cpu max` (FEAT_VHE, 16 KB granule) lets us exercise already. **Both are now the default** (`WEL2_DEF_E2H = 1`, `WEL2_DEF_GRAN = 14` in `boot.h`); the old configuration stays selectable for comparison. Choice at boot, read in `stage1_build` with the MMU off from `/chosen/bootargs` (QEMU `-append`; every `run-*.sh` takes `WEL2_ARGS="..."`):

| argument | meaning |
|---|---|
| `wel2.e2h=0\|1` | `HCR_EL2.E2H` the layer runs with. Written before the EL2 MMU is on, on **every** core in `s1_enable` (HCR_EL2 is per core). The value that reads back wins: on the M1 (bit stuck at 1) a request for 0 is logged as "stuck" and the layer runs with 1. |

**16 KB granule** (`../include/wel2_pt.h`, `../vgic/pt.c`, `../include/wel2_maps.h`, `../vgic/maps.c`; one builder for both stages, both granules). Geometry [verified: Arm ARM D8.2.9, Tables D8-26, D8-27, D8-28, D8-29, D8-31]:
- **Stage 2, 40-bit IPA** (`T0SZ` 24): 16 KB start at level 1 with 16 entries of 64 GB (`VTCR_EL2.SL0 = 0b10`, `TG0 = 0b10`); 4 KB starts at level 0 with 2 entries (`SL0 = 0b10`, `TG0 = 0`). `SL0` is `2 - level` for 4 KB and `3 - level` for 16 KB. `VTCR_EL2.PS = min(PARange, 40 bit)`.
- **EL2 stage 1**: 16 KB uses 36-bit VA (`T0SZ` 28, start level 2, one 16 KB table of 2048 entries of 32 MB = 64 GB; the M1's DRAM and MMIO are below 64 GB), 4 KB keeps 39-bit (`T0SZ` 25).
- **Blocks:** 16 KB has **no level-1 block** without FEAT_LPA2 (Table D8-27): the largest block is 32 MB at level 2, pages are 16 KB; 4 KB keeps 1 GB / 2 MB / 4 KB. The builder uses the largest aligned block and splits a block when a finer map (the GIC holes, the carve-out, the text/rodata pages) overlaps it. High device window (64 GB to 1 TB, PCIe high ECAM `0x4010000000` and MMIO `0x8000000000` of virt) costs one level-2 table per 64 GB with 16 KB (15 tables), 2 level-1 tables with 4 KB.
- **Pools:** stage 2 uses 19 x 16 KB = 304 KB (7 x 4 KB = 28 KB with 4 KB), stage 1 two tables with 16 KB (three with 4 KB); static pools of 24 and 8 tables (`WEL2_S2_POOL_BYTES`, `WEL2_S1_POOL_BYTES`), and the linker still asserts that image + stacks fit the first 2 MB.
- **Carve-out and holes:** the layer carve-out (first 2 MB of RAM, 2 MB is a multiple of 16 KB), the GICD (64 KB) and the eight GICR frames (8 x 128 KB) are all 16 KB multiples and 16 KB aligned, so the holes are exact for both granules (`test_pt.c` walks every 4 KB frame of them). The text/rodata boundaries of the layer are 16 KB aligned in `linker.ld`; the image start `0x40080000` is too. The guest RAM base `0x40200000` is 16 KB (and 2 MB) aligned; the first 32 MB block of RAM is a level-3 table of pages (carve-out hole), the rest are 32 MB blocks. A RAM end that is not 32 MB aligned costs 16 KB pages at the end (the FDT range is rounded to 2 MB, `wel2_ram.h`).
- **Stage-1 (guest, Windows) 4 KB pages over 16 KB stage-2 pages:** the layer maps RAM and devices 1:1 and in blocks, so a 4 KB guest mapping inside a 16 KB stage-2 page just works; only emulated windows need care (next list).

## pirq indirection and re-target on CPU_OFF (M2.x-2/3; #67; design `docs/design/watari-el2-devirq/`)
- **Layering.** Physical SPI arrival -> `pirq` -> vINTID, so the QEMU GIC backend (today, `pirq_qemu.c`) and the future AIC backend (#59) share one path. Policy: `../vgic/pirq.c` (`wel2_pirq.h`, host-tested with a fake backend in `../tests/fake_pirq.h`); numbers: `../vgic/intr_map.c` (`wel2_intr_map.h`, shared with `tools/acpigen`). `cpuif.c` no longer keeps `g_spi_masked`/`g_spi_edge`: it calls `pirq_arrive` / `pirq_line_low` + `pirq_finish` / `pirq_effect`.
- **QEMU behaviour is unchanged**: identity map for SPIs 32..959, `auto_masks = false` (a level SPI is disabled at the GICD when taken and re-enabled at the guest's deactivate), the guest's `ICFGR` decides the trigger (F-25), a guest enable unmasks at once (`strict_level = false`).
- **Re-target.** `psci.c` CPU_OFF calls `pirq_vcpu_off` before the interface is torn down: SPIs the guest routed to that vCPU (or that were already parked on it) are re-routed physically to the lowest online vCPU; `el2_secondary_main` calls `pirq_vcpu_on`, which restores them if `GICD_IROUTER` still names the core. The vGIC model is not touched: `IROUTER` still reads back what the guest wrote, and an SPI routed to a vCPU that is off stays pending for it, as GICv3 requires (a guest migrates it, as Linux does when it offlines a core).
- **Test (`run-m1-3.sh`, both modes):** after the RTC SPI test, core 3 goes off while SPI 34 is still routed to it; the next alarm must be taken at EL2 on core 0 (log `physical SPI 34 taken on cpu 0`, before the payload migrates the route), stay pending, and reach core 0 after the payload writes `IROUTER`. Mutation check: without `pirq_vcpu_off` the script reports MISSING for both the re-route line and the ordering.
- **AIC contract on the host only** (no AIC code yet): `auto_masks` (the event read masked the source: level is unmasked at the guest's deactivate, edge at injection), `strict_level` (a guest re-enable does not unmask a held level source), a platform trigger table that overrides the guest's `ICFGR`, default-deny allow-list (an unlisted source is masked and counted).

## Hardening follow-ups (#60, #64; QEMU TCG + host tests; F-26)
- **Cross-core kick for LR eviction.** `cpuif_kick_others` used to kick a core only if it had a free list register; a better interrupt for a core with four pending-only LRs waited for that core's next exit. Now the sender asks `vcif_fill_can_progress()` (host-tested: free LR, or an evictable pending-only LR of strictly worse priority) on the target's mirror and sends the physical SGI 15; the target's `cpuif_flush` evicts. The predicate is false again after that flush, so two cores with full LRs cannot kick each other forever (the F-20 kick-storm guard stays). `run-m1-3.sh` (both modes): cpu 1 stops its timer, masks IRQs and spins; cpu 0 sends SGIs 3..6 (low priority, they fill the 4 LRs) and then SGI 11 (much better); cpu 1 unmasks and must take 11, 3, 4, 5, 6. Mutation check: with the old "free LR only" condition the same test delivers 3, 11, 4, 5, 6 and fails. Stats line: `cross-core kicks to evict a worse pending LR`. A core whose LRs are all active, or hold interrupts at least as good, is still not kicked.
- **`ICC_HPPIR1_EL1` in TRAP_EMULATE: the hypothesis of F-22 is confirmed, no code change.** IHI 0069H.b 12.2.12 (ICC_HPPIR1_EL1) and 12.3.10 (ICV_HPPIR1_EL1) say "the INTID of the highest priority pending interrupt" and only fall back to a special INTID when it is "not observable" (group disabled, not for this register); ICC_IAR1_EL1 (12.2.10) adds "if that interrupt is of sufficient priority for it to be signaled". So HPPIR ignores PMR and the running priority, IAR does not. `vcif_hppir1` already did that; host test `t_hppir_ignores_pmr_and_running_priority` pins it down (PMR masks, running priority above it, tie-break by lowest INTID, group disabled gives 1023). [verified: spec text]
- **PRIbits / PREbits.** ICH_VTR_EL2 (12.4.9): PRIbits+1 is 5..7 (the model allowed 8: corrected, F-26), PREbits+1 is 5..PRIbits+1, the number of `AP0Rn/AP1Rn` registers is 2^(PREbits-5) (12.4.1/12.4.2), the minimum `BPR0` is 2/1/0 for 5/6/7 preemption bits and the Group 1 minimum is one more (12.3.3/12.3.4). Host tests `t_preemption_widths` (six PRI/PRE combinations: register count, minimum BPR, priority bits, nested preemption), `t_ap_upper_registers` (AP1R1/AP1R3 bits for PREbits 6 and 7), `t_fine_lr_priorities` (LR priorities finer than the model's 5-bit granule), `t_width_clamps`. `cpuif.c` already sized the hardware AP loop with 2^(PREbits-5). Not exercised on QEMU (its ICH_VTR_EL2 has PRIbits = PREbits = 5): the register mapping beyond AP1R0 is host-test only. The vGIC model itself still stores 5 priority bits (`PRIO_MASK 0xF8`), so a guest-visible priority is a multiple of 8 whatever the hardware width.
- **RAM map from the FDT /memory node.** `stage1_build(fdt)` (MMU still off) reads `/memory/reg` with `fdt_get_memory`, which feeds `wel2_ram_from_reg` (`../include/wel2_ram.h`, `../vgic/ram_map.c`, host tests `test_ram_map.c`: -m 512M / 2G / 4G, a half-filled last GB, rounding to 2 MB, wrap, clamp at 512 GB, cell counts 1+1 and 2+2). Stage 1 maps 2 MB blocks inside the first GB where RAM exists, a 1 GB block for each fully filled GB, a level-2 table for a partly filled last GB, and nothing else (the 0-1 GB device map is unchanged); stage 2 does the same with device blocks around the RAM, and the chain build still hides the layer in 4 KB pages. `PSCI CPU_ON` accepts entry points below `g_ram_end` (replaces the fixed `GUEST_RAM_END`). The boot log prints `RAM from the FDT /memory node, base ...` and `RAM end = ...`: 0x60000000 with `-m 512M`, 0xc0000000 (`run-m1-4.sh`, `-m 2G`), 0xa0000000 with `-m 1536M` (partial last GB, checked by hand with `-smp 4`). Without a usable node (not a QEMU FDT, base not 0x40000000) the old map to 0x13fffffff applies and the log says so. `fdt.c` and `ram_map.c` are built with `-mstrict-align` because the stage-1 build calls them with the MMU off. Windows with `-m 4G` (`RAM end = 0x140000000`, all three secondaries up with the new `CPU_ON` limit): confirmation run `CPUIF=trap MSI=gicv2m ... TAG=hard60-trap LOGDIR=m2x run-m2.sh`, lock screen at 9 min, `m2-login.sh login`, desktop (Start bar, Edge, Recycle Bin) 4 min later; screenshot `$WATARI_DATA/logs/m2x/hard60-trap/desktop-confirm.png`. No FATAL/UNEXPECTED line in the serial log.
- **#64, cheap ones.** IDbits: `vgic_config.idbits` comes from the physical `GICD_TYPER.IDbits` (`gic_phys_idbits`), kept in 14..24; it sets `GICD_TYPER.IDbits` for the guest, the largest LPI INTID the model accepts, and `ICC_CTLR_EL1.IDbits` (0 = 16 bits, 1 = 24 bits, `vcif_set_idbits`, EOIR/DIR masks). QEMU reports 16 bits, so nothing changes there. LPI queue overflow: `vgic_lpi_dropped()` counts the LPIs lost to a full per-vCPU queue; stats line `LPI queue overflows (LPIs dropped)`. Host tests in `test_vgic_lpi.c`, `test_vcif.c`.
- **Not done (needs the M1 hardware):** cache maintenance for the EL2 page tables and for the property table the layer reads (#64), the SEIS/PRIbits/PREbits values of the real GIC. (The E2H = 1 execution of the stage-1 layout is done in QEMU, see "E2H = 1 and the 16 KB granule"; it still needs the M1 to be seen with the bit really stuck.) Also still open from #64: `EnableLPIs` cannot be cleared on the physical redistributor after CPU_OFF/CPU_ON.

## Position independence (T6a)
The image is linked at address 0 as a PIE (`-fpie -fvisibility=hidden`, `pie.h` makes every declaration hidden so there is no GOT; `ld.lld -pie --no-dynamic-linker -z norelro`, no RELR). `.dynsym/.dynstr/.hash/.dynamic` are discarded; `.rela.dyn` stays in the image between `__rela_start` and `__rela_end`. `start.S` (boot core, MMU off, DAIF masked first) takes `x9 = adr _start`, requires it 16 KB aligned, applies every `R_AARCH64_RELATIVE` entry (`*(base + r_offset) = base + r_addend`; any other type parks with `x0 = "RELO"`, nothing can be printed before the console is known), then sets the stack, zeroes `.bss` and runs `DC IVAC` over the whole block from `_start` to the end of the stacks, because the relocated `.data` and `.data.rel.ro` are written with the MMU off. `start.S` uses only `adr`/`adrp` (`adr_l` macro), never a literal pool. [verified: Arm ARM D7.5 for the maintenance, ELF psABI for AArch64 for the relocation type 1027]

Run-time layout, all from `_start` (`stage1.c`, `boot.h`): `g_layer_base` = address of `_start`; `g_carve_size` = 2 MB (QEMU; the M1 will use its 32 MB block) and `g_carve_base` = `g_layer_base` aligned down to it; the default RAM is 4 GB from `g_carve_base`. `EDK2_FDT_ADDR` = `g_carve_base` and `EDK2_ENTRY` = carve end + `0x80000` (what the QEMU `-device loader,addr=0x40280000` for EDK2 matches). The stage-1 text/rodata split, the stage-2 carve-out hole and the FDT patch use these values. The header still says `text_offset` 0x80000, which is where QEMU loads it; `image_size` covers the image, `.bss` and all stacks.

Build checks: `check-pie.sh` (run after every link, and by `make -C el2 test` through `make -C el2/boot check`): only `R_AARCH64_RELATIVE` dynamic relocations (41 today), 8-aligned targets in the data sections, no `.got`, `.relr.dyn`, `.dynsym` sections, linker symbols section-relative (not ABS), `_start` at 0, and no `ldr xN, =...` in `start.S`. `run-moved.sh` loads the same binary at `0x40100000` (header `text_offset` patched) as a proof that the relocation really moves the image.

Early park codes (`start.S`, `park_x0`): a core that stops before the C code leaves a code in `x0` (read it over the m1n1 proxy): `0xBAD00001` load address not 16 KB aligned; `0xBAD00002` not the boot core (normal for the other cores); `0xBAD00003` not at EL2; `0xBAD00004` a dynamic relocation that is not `R_AARCH64_RELATIVE`; `0xBAD00005` secondary core started below EL2; `0xBAD00006` secondary core outside the stack slots (`x1` = its MPIDR with bit 63, also stored in `g_bad_mpidr`). `stage1_build` additionally checks at run time that `_start` to `__layer_end` lies inside the carve-out and halts with a UART message otherwise. Each secondary core does a `DC IVAC` of its own stack slot and of `g_s1` before it enables its caches [hypothesis: insurance, QEMU cannot show the need]. `run-moved.sh` (see above) is run by hand, not by `run-all.sh`.

## Framebuffer output (T5b; host tests `test_fb.c`, QEMU unchanged: no framebuffer there)
- **Source.** `stage1_build` (MMU off) calls `fdt_get_framebuffer`: the node `/chosen/framebuffer@*` with compatible `simple-framebuffer`, `reg`, `width`, `height`, `stride` (bytes), `format` `x8r8g8b8` or `x2r10g10b10` (m1n1 fills it; j293: 2560 x 1600, base `0x9e2570000`, 30 bit) [verified: DESIGN section 7, re/m3a-ehw0-measurements.md]. Only these properties are read; nothing else of the FDT is printed. Unusable geometry (stride < 4 * width, unaligned, unknown format, wrapping) means no framebuffer. `g_fb` (util.c) is all-zero without one and every call is then a no-op.
- **Output.** `putc_`/`puts_` mirror to a text console (original 5 x 7 font `../vgic/font5x7.h`, integer scale = width / 400 clamped to 1..6 (T6h: 6 on the j293, about 70 columns), white on black, lower case drawn as upper case, wrap at the right edge, scroll by clearing the scrolling text area only; layout and the status band: next section). `checkpoint(n)` paints square n (24 px, pitch 28 px, from x = 8, top row) green; `checkpoint_state(n, 0|1|2)` amber/green/red; `checkpoint_fail()` repaints the current square red and is the first thing `fatal()` and `fatal_msg()` do. Guest checks use squares from 16 on (S13/S14). The code uses only aligned volatile 32-bit stores and no lock, so `checkpoint()` works with the MMU off (before `s1_enable`).
- **Mapping.** EL2 stage 1 maps the framebuffer Normal non-cacheable: `MAIR_EL2` Attr2 = `0x44` [verified: Arm ARM MAIR_EL2 encoding], outer shareable, XN (`wel2_s1_map_fb`, `../vgic/maps.c`). It must lie wholly above the RAM (j293: `0x9e2570000` above the RAM top `0x9df610000`); otherwise the framebuffer is switched off with a warning. It is never given to the guest: `main.c` adds a stage-2 hole for it. Whether the panel keeps showing what was drawn after m1n1's `fb_shutdown` is **[hypothesis]** until day 2.
- **Open design point (T11).** Because the framebuffer belongs to the layer (stage-2 hole), a later EDK2 GOP driver in the guest cannot reach it. If the guest should draw on the panel, the layer must hand the framebuffer over explicitly (a stage-2 mapping for it plus the geometry in the guest info block) and stop its own text output; not designed yet.

## Trap configurations, ID registers, PAuth, boot ladder (T6g; host tests `test_vcif.c`, `test_idreg.c`, `test_chk.c`; QEMU `run-step.sh`, `run-tid3.sh`, `run-g5b-negative.sh`, `run-m1guest.sh` in all three modes)
- **Three virtual-CPU-interface modes** (`wel2.cpuif=hw|trap|trap-notc`, `CPUIF=` in every run script, `run-all.sh` runs all three). `ICH_HCR_EL2` base value (`vcif_hcr_base()`, `../vgic/vcif.c`, host-tested): `hw` = `En`; `trap` = `En | TALL0 | TALL1 | TC | TDIR`; `trap-notc` = `En | TALL0 | TALL1 | TDIR` (`TDIR` only where `ICH_VTR_EL2.TDS` says the trap exists). In `trap-notc` the guest's `ICC_PMR_EL1`, `ICC_CTLR_EL1` and `ICC_RPR_EL1` are served by the hardware virtual interface (`ICV_*` against `ICH_VMCR_EL2` and the `ICH_AP*R_EL2`); the model keeps no copy of PMR or EOImode (`vcif.c` reads them only from `c->vmcr`, which `icc_emulate()` reloads from `ICH_VMCR_EL2` before every emulated IAR/EOIR/DIR: `t_notc_vmcr_by_hardware`). On the M1 only `trap` and `trap-notc` are accepted: `wel2.cpuif=hw` there prints a log line and the mode stays `trap` (DESIGN 5.4 / PLAN S12b). The mode reaches the guest in the info block (`cpuif_mode`) and in `WEL2_STATS`; G5b judges the `TC` group against it: under `trap` the PMR/CTLR/RPR counters must move, under `trap-notc` and `hw` they must stay still. `run-g5b-negative.sh` proves both directions with the test knobs `wel2.test=tcoff` (reports `trap`, runs without `TC`) and `wel2.test=tcon` (reports `trap-notc`, runs with `TC`): G5b FAILs and the text names `TC`. In `trap` mode an ICC access that nothing emulates is logged (`unemulated ICC access S3_0_C<CRn>_C<CRm>_<op2><R|W>`, also in the panel's error line) before the fatal register dump; whether `TC` traps `ICC_SRE_EL1` on the real GIC is [hypothesis] (DESIGN 5.4). The ID-register trap is decoded before the ICC emulation, and only CRn 12 / CRn 4 reach the ICC code (no ICH register is read for anything else). **QEMU cannot show the SEIS erratum, so `trap-notc` passing here only proves the logic; whether `TC` misbehaves is day 2, rung L3** [hypothesis].
- **ID registers (`HCR_EL2.TID3`).** On the M1 `TID3` is on by default (EDK2's `ArmGicDxe` and Windows read `ID_AA64PFR0_EL1.GIC`); on QEMU it is opt-in with `wel2.tid3=1`; `wel2.tid3=0` turns it off on the M1. The EC 0x18 trap of a read in the group (op0 3, op1 0, CRn 0, CRm 1..7) is answered in `idreg.c`/`../vgic/idreg_tbl.c`: the real register read at EL2 for the 36 encodings the table lists (ID_PFR*/ID_DFR*/ID_AFR0/ID_MMFR*/ID_ISAR*/MVFR*/ID_AA64*), `ID_AA64PFR0_EL1.GIC` [27:24] forced to 1, every other bit unchanged (PAuth fields included), an encoding not in the table reads 0 and is never read at EL2; neither are the AArch32 ID registers (CRm 1-3) when `ID_AA64PFR0_EL1` shows AArch64-only EL0/EL1, `ID_AA64ZFR0_EL1` without SVE and `ID_AA64SMFR0_EL1` without SME (they read 0: an UNDEF at EL2 mid-boot would be fatal) (`ELR` advanced by 4). The table is from memory of the Arm ARM **[hypothesis]**; registers added by newer architecture revisions (`ID_AA64PFR2`, `ID_AA64ISAR3`, ...) read 0 in the guest. The guest's G3 prints all 36 as `IDREG` lines; `run-tid3.sh` runs the guest with and without `wel2.tid3=1` and requires identical lines, a TID3 counter (`stats: TID3 ID-register reads emulated`) of at least 36 with the trap and none without. QEMU `-cpu max` already reports `GIC = 1`, so the override itself (0 to 1, nothing else touched) is checked by `test_idreg.c`.
- **Pointer authentication.** `HCR_EL2.API | APK` (bits 41, 40) are set on every platform when `ID_AA64ISAR1_EL1` (APA/API, GPA/GPI) or `ID_AA64ISAR2_EL1` (APA3/GPA3) report an algorithm (`cpu_has_pauth()`, `main.c`); the guest owns the keys (the layer is built without PAuth). The info block flag `F_PAUTH` mirrors the bits, so G3 does a real `PACIA`/`AUTIA` sign/authenticate and a tamper check on QEMU `-cpu max`; `run-m1guest.sh` no longer needs `-cpu max,pauth=off`.
- **Boot ladder (`wel2.step=N`, DESIGN 9).** `stage1.c` reads the argument first thing after the relocation and the platform switch. `wel2.step=1` (rung L1) calls `g_plat->system_reset()` right there: no console, no framebuffer, no stage 1 (M1: the watchdog from the FDT node; if there is none the layer goes on and `el2_main` stops with a message; QEMU: PSCI `SYSTEM_RESET`, which ends a `-no-reboot` QEMU). `wel2.step=2` (rung L2) resets after checkpoint 5 (`CPU_INIT`): the banner, the platform discovery, the interrupt controller and the per-core platform init are done, the guest's stage 2 and the virtual CPU interface are not. Steps 3, 4 and 5 are rungs L3 to L5: the info block's `checks` mask selects G1-G6, G1-G8, all (G11, the final reset, always runs). The band shows `RUNG L<n> STEP <s>` from checkpoint 0 on. `run-step.sh` checks steps 1, 2 and 3 in QEMU.

## Checkpoints (T6g; the squares of the photo, `../include/wel2_chk.h`, `../include/wel2_hvc.h`)
`test_chk.c` compares this table with the code row by row. Each layer checkpoint also prints one line `Watari EL2: checkpoint <n> <NAME>` (decimal), so a QEMU run shows the same progress as the panel. Squares 0-15 are the layer's, painted green when reached (`checkpoint(n)`); 16 and up are the test guest's checks (`WEL2_CHECKPOINT`, square = 16 + check number): amber running, green pass, red fail, **grey skipped** (`WEL2_CHKSTATE_SKIP` = 3, counted as SKIP in the band; G8 reports it when the physical timer is not exposed).

| Square | Name | Meaning |
|---|---|---|
| 0 | `RELOCATED` | `start.S` relocated the image and `stage1_build` found the framebuffer; MMU still off. (`wel2.step=1` resets before this.) |
| 1 | `STAGE1_ON` | `s1_enable` returned: the EL2 MMU and caches are on. |
| 2 | `BANNER` | The console is known, the banner and the stage-1 report are printed. |
| 3 | `DISCOVER` | Platform discovery: the cores are known (FDT cpu list on the M1, redistributor walk on QEMU). |
| 4 | `IRQ_READY` | The vGIC model and the SPI policy (AIC or physical GICD backend) are ready; the boot core can take SPIs. |
| 5 | `CPU_INIT` | Platform init done: `init_boot` (interrupt controller shared part), the Apple FIQ module / GIC cpu interface, the WHOAMI check. `wel2.step=2` resets here. |
| 6 | `STAGE2_ON` | The guest's stage 2 is built and enabled. |
| 7 | `CPUIF` | The virtual CPU interface is on (`trap`, `trap-notc` or `hw`). |
| 8 | `ENTER_GUEST` | About to `eret` to the guest (the test guest or EDK2). |
| 9 | `CPU_ACCEPT` | A `CPU_ON` was accepted (M1; the core has not arrived yet). |
| 10 | `CPU_ARRIVE` | A started core reached the layer and is about to `eret` to its guest entry (M1). |
| 11 | `HALT` | `SYSTEM_OFF`, or `SYSTEM_RESET` without a watchdog node: the layer halts (M1). |
| 12-15 | (free) | Not used. |
| 17 | `G1` | Guest check G1 (square = 16 + check number; the guest reports `WEL2_CHECKPOINT` n). |
| 18 | `G2` | G2. |
| 19 | `G3` | G3: `GIC` field reads 1, PAuth sign/authenticate, ID group readable. |
| 20 | `G4` | G4. |
| 21 | `G5a` | G5a: the `TALL1` group traps. |
| 22 | `G5b` | G5b: the `TC` group (PMR, CTLR, RPR) against the configuration. |
| 23 | `G6` | G6. |
| 24 | `G7` | G7: virtual timer. |
| 25 | `G8` | G8: physical timer (grey = skipped). |
| 26 | `G9` | G9: secondary core up. |
| 27 | `G10` | G10: `CPU_OFF` and `CPU_ON` again. |
| 28 | `G11` | G11: the final `SYSTEM_RESET`. |

A fatal error (`fatal()`, `fatal_msg()`, `fatal_dump()`) repaints the current square red and writes the reason into the last-error area of the band (T6h hooks, now wired).

## Reading the screen from a photo (T6h; for the T8 procedure)
On the hardware day only photographs of the M1 panel (2560 x 1600, j293) reach Claude. Everything that matters is therefore written in words, in large letters (scale 6: a character cell is 36 x 54 px, 70 columns, 23 text rows), not only in colours. Layout, top to bottom (numbers for 2560 x 1600; the layout is computed from the width, see `wel2_fb.h` and `test_fb.c`):

| Area | Pixels (y) | What it shows |
|---|---|---|
| Checkpoint squares | 0-31 (squares 24 px, pitch 28 px, from x = 8) | Square n for checkpoint n: 0-15 are the layer's boot steps (table in "Checkpoints" above), 16 and up are the guest's checks (`WEL2_CHECKPOINT`, guest check k = square 16 + k, G1..G11). Green = reached/ok, amber = running, red = failed, grey = skipped, no square = not reached. The squares are small on purpose: read the band below, not the squares. |
| Status band (dark blue, 3 lines) | 32-193 | Line 1 `WATARI EL2  RUNG L<n> STEP <s>`: ladder rung and `wel2.step` (`-` until the boot code reports it). Line 2 `CHECKPOINT <n> <OK/RUNNING/FAIL/SKIP>`, for a guest check also `(GUEST CHECK <k>)`, plus an optional label; the text colour is green/amber/red like the square. Line 3 `GUEST PASS <p> FAIL <f> SKIP <k>`: one count per guest check in its latest state (red text when f > 0). Never scrolled. |
| Last error (2 lines) | 194-301 | `LAST ERROR: NONE` in grey, or the error text in red (up to 2 lines, 128 characters). Set automatically to `CHECKPOINT <n> FAILED` when a square turns red and to `FATAL AT CHECKPOINT <n>` by `fatal()`/`fatal_msg()` (via `checkpoint_fail`), or explicitly with the message. Never scrolled, so it is still there after the log has scrolled past. |
| Grey rule | 302-305 | Separates the fixed part from the log. |
| Scrolling log | 306-1599 | The layer's text output (what also goes to the UART, including the guest's `WEL2_LOG` lines). The legend ("SQUARES 0-15: LAYER STEPS, 16+: GUEST G1-G11" / "GREEN = OK  AMBER = RUNNING  RED = FAIL  GREY = SKIP") is printed at its top on the first drawing call and again every time the area fills up and is cleared (the log restarts below it); when the area is full it is wiped and output restarts at the top, so older lines are gone: ask for a photo at each rung, not at the end. |

How to read a photo: (1) the band tells where the run got to (rung, step, last checkpoint, guest counts); (2) if the error line is not `NONE`, copy it exactly; (3) the bottom log shows the last few lines before the stop; (4) the squares row is a cross-check (a missing square after a red one means the run stopped there). A black screen with nothing at all means nothing was drawn (no framebuffer in the FDT, or the panel was switched off by m1n1's `fb_shutdown`, **[hypothesis]** until day 2) or the display is asleep: press a key / move the trackpad and photograph again. The first drawing call wipes the whole panel (m1n1's last image included) to black.

Boot-code hooks (T6g: all wired; the band also updates itself from every `wel2_fb_checkpoint`):
- `wel2_fb_set_rung(&g_fb, rung, step)` in `stage1.c` right after the framebuffer lookup, from `wel2.step` (rung = min(step, 5) for L1..L5; nothing is set without a step, the band shows `-`).
- `wel2_fb_set_error(&g_fb, msg)` in `fatal_msg()`, `fatal_dump()` (the reason) and `fatal()` (the vector name unless a reason is set), after `checkpoint_fail()`.
- Squares for skipped guest checks: the vendor hypercall `WEL2_CHECKPOINT` with state `WEL2_CHKSTATE_SKIP` (3) paints grey (`checkpoint_state`); the guest's `skip()` sends it (G8).
- `wel2_fb_checkpoint_text(&g_fb, NAME)` in `layer_checkpoint()` (`main.c`): the checkpoint line of the band carries the name of the layer checkpoint.
Host test: `make -C el2 test` (`t_band_2560`, `t_error_persists_across_scrolls`, `t_band_800x600`, `t_band_small_screens`, `t_fatal_error_text`); `WEL2_FB_PPM_2560=<file> el2/build/test_fb` writes the 2560 x 1600 PPM of the band test to look at.
